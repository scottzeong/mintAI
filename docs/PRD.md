# Scriptorium — 저술을 위한 개인 지식 정제 시스템

**설계 문서 v0.3**
작성일: 2026-07-25
상태: 초안 — D7·D8 반영 (오픈 액세스 전용 운영 확정)

> **원안 (原案)**
> *"자신의 생각들을 키워나갈 수 있는 글쓰기 도구"*
>
> — 설계가 복잡해질 때마다 이 한 줄로 돌아온다.
> **저장**이 아니라 **성장**. **관리**가 아니라 **글쓰기**.

---

## 0. 한 줄 정의

> 흩어진 생각을 AI 리서치와 **인간의 요약**을 거쳐 신뢰 가능한 지식 카드로 정제하고,
> 그 카드만을 재료로 **한 권의 책을 완성**하는 개인용 저술 시스템.

---

## 1. 문제 정의

### 1.1 저술가가 실제로 겪는 문제

| 단계 | 실제 고통 |
|---|---|
| 착상 | 아이디어는 계속 떠오르는데 휘발된다 |
| 조사 | 자료는 모으는데 읽지 않고 쌓이기만 한다 (수집 중독) |
| 이해 | 읽어도 내 것이 안 된다. 3개월 뒤 남의 글처럼 낯설다 |
| 집필 | 막상 쓰려면 재료가 없다. 어디에 뭘 조사했는지 모른다 |
| 검증 | "이 주장 근거가 뭐였지?" 출처를 다시 찾느라 시간을 태운다 |
| 일관성 | 장마다 문체와 논조가 다르다 |

### 1.2 기존 도구가 실패하는 이유

**Notion / Obsidian:** 저장은 되지만 정제되지 않는다. 클리핑 무덤.
**ChatGPT 직접 사용:** 결과물이 내 지식이 아니다. 문체도 내 것이 아니다.
**AI 노트 앱 (요약 자동 저장류):** 6개월 뒤 *내가 모르는 내용으로 가득 찬 내 노트*가 된다. 검색 가능한 쓰레기더미.

### 1.3 핵심 통찰

책은 **정보량**으로 쓰이지 않는다. **저자가 소화한 이해의 총량**으로 쓰인다.
따라서 시스템은 정보를 많이 모아주는 방향이 아니라, **소화되지 않은 정보의 저장을 금지하는** 방향으로 설계되어야 한다.

## 2. 설계 원칙 (변경 불가 · 이 문서의 헌법)

### 원칙 1. AI가 쓴 문장은 데이터베이스에 남지 않는다

AI 리서치 결과는 **휘발성 작업 공간**에만 존재하며 소화 완료 시 폐기된다.
Knowledge Library에 영구 저장되는 산문은 100% 인간이 타이핑한 것이다.

> **왜:** 저자가 이해하지 못한 문장이 원고에 들어가는 것을 구조적으로 차단한다.
> 요약이라는 노동을 강제함으로써 "저장 = 학습"을 성립시킨다.

### 원칙 2. 단, 사실 데이터는 승계한다

출처 URL, 제목, 저자, 발행일, 인용 원문(따옴표 안 원본)은 AI 산문이 아니라 **사실**이므로 저장한다.
이것이 없으면 3개월 뒤 근거를 추적할 수 없고, 책의 참고문헌을 만들 수 없다.

### 원칙 3. 집필은 종착점이 아니라 조사의 트리거다

집필 중 "여기 근거가 약하다"를 발견하는 것이 가장 정확한 리서치 요청이다.
따라서 파이프라인은 직선이 아니라 **루프**다.

### 원칙 4. 생성 AI는 Library 밖의 지식을 사용할 수 없다

초고 생성 시 모델의 사전지식 사용을 금지하고, 선택된 카드만을 컨텍스트로 준다.
카드에 없는 내용은 `[근거 부족: 카드 없음]`으로 표시하게 한다.

> **왜:** 이 규칙이 없으면 원고에 저자가 모르는 문장이 섞이고, 원칙 1이 무의미해진다.

### 원칙 5. 한 권의 책 = 하나의 목차 = 하나의 목소리

카드는 자유롭게 쌓되, 저작물(Work)은 항상 목차 구조에 종속된다.
"카드가 어느 장에 쓰일지" 매핑되지 않으면 영원히 안 쓰인다.

## 3. 사용자 및 범위

**단일 사용자.** 개인 저술가(=본인). 멀티유저·협업·공유 없음.
**동시 진행 저작물:** 1~3권 가정.
**목표 규모:** 카드 300~800장 / 저작물당 원고 8~15만 자.

### 3.1 v1 범위 밖 (명시적 제외)

- 다중 사용자, 권한, 공유
- 모바일 네이티브 앱 (모바일은 캡처 전용 웹만)
- 실시간 협업 편집
- 출판사 포맷 자동 변환 (v2)
- 음성 입력 (v2)

## 4. 전체 파이프라인

```
                      ┌─────────────────── 루프 ───────────────────┐
                      │                                            │
                      ▼                                            │
 [1] 착상          [2] 리서치 요청      [3] AI 리서치      [4] 소화(Digest)
  인간               인간                 AI                 인간
  거친 생각          "무엇을 더           자료 수집          읽고 → 내 언어로 요약
  1줄~1문단          알아야 하나"         출처 정리          ⚠ AI 산문 여기서 폐기
                      │                                            │
                      └──────────────┐                             ▼
                                     │                    [5] Knowledge Card
                                     │                        영구 저장
                                     │                        인간 텍스트 + 출처
                                     │                             │
                                     │                             ▼
                                     │                    [6] 목차 매핑
                                     │                        카드 → 장/절 배치
                                     │                             │
                                     │                             ▼
                                     │                    [7] 초고 생성
                                     │                        AI, 카드만 사용
                                     │                             │
                                     │                             ▼
                                     │                    [8] 퇴고
                                     │                        인간, 최종 원고
                                     │                             │
                                     └───── 근거 부족 발견 ◄────────┘
                                            = 새 리서치 요청
```

**루프의 의미:** [7]에서 AI가 `[근거 부족]`을 표시하면 그것이 자동으로 [2]의 리서치 요청 후보가 된다. 이 되먹임이 이 시스템의 엔진이다.

## 5. 데이터 모델

### 5.1 ERD 개요

```
Work (저작물)
 └─ Outline Node (장/절, 트리)
      └─ CardAssignment ──┐
                          │
Idea (착상)               │
 └─ ResearchRequest       │
      └─ ResearchRun ⚠휘발│
           └─ (소화) ─────┴──► KnowledgeCard ◄── CardLink ──► KnowledgeCard
                                    │
                                    ├─ Source (출처, 사실 데이터)
                                    └─ Excerpt (직접 인용 원문)

Manuscript (원고)
 └─ Section Draft ── cites ──► KnowledgeCard
```

| 필드 | 타입 | 설명 |
|---|---|---|
| id | uuid | |
| work_id | fk? | |
| title | text | 인간 작성 |
| summary | text | **인간 작성 본문. AI 붙여넣기 방지 대상** |
| key_points | json[] | 인간 작성 불릿 |
| my_take | text | **내 해석/비판/적용 아이디어** (요약과 분리) |
| card_type | enum | `fact` / `concept` / `argument` / `case` / `data` / `quote` / `counter` |
| confidence | int 1-5 | 내가 얼마나 확신하는가 |
| tags | json[] | |
| embedding | vector | 유사 카드 탐색용 |
| status | enum | `active` / `needs_recheck` / `retired` |
| digested_at | ts | |

**주장 카드 전용 논증 필드** (`card_type = argument`일 때 필수)

| 필드 | 타입 | 설명 |
|---|---|---|
| claim | text | 주장 |
| grounds | text | 근거 |
| warrant | text | 근거→주장 연결 논리 |
| qualifier | text | 적용 범위·조건 |
| rebuttal_conditions | json[] | **이 주장이 무너지는 조건 (인간 작성 필수)** |

각 `rebuttal_condition` 항목:
```json
{ "condition": "신뢰가 담합을 낳는 경우",
  "resolution": "counter_card" | "qualifier_narrowed" | "limitation_accepted" | null,
  "ref_card_id": "uuid?",
  "note": "text" }
```

> `resolution = null`인 조건이 남아 있으면 G2 게이트에서 차단된다.

> `summary`(객관적 이해)와 `my_take`(주관적 해석)를 **분리**하는 것이 중요하다.
> 집필 시 전자는 설명 문단, 후자는 저자의 목소리 문단으로 서로 다르게 쓰인다.
> 섞어두면 나중에 어디까지가 사실이고 어디부터 내 의견인지 구분이 안 된다.

## 6. 상태 전이

### 6.1 리서치 요청

```
queued ──[AI 실행]──► running ──► awaiting_digest ──[인간 요약 저장]──► digested
   ▲                                    │
   └──────[14일 미소화 → 자료 폐기]──────┘
                                        └──[가치없음 판단]──► dropped
```

### 6.2 목차 노드

```
empty ──[카드 1장 배치]──► researching ──[G1~G5 전부 통과]──► ready
                                                              │
                              ┌───────[초고 생성]─────────────┘
                              ▼
                          drafted ──[인간 퇴고]──► final
                              │
                              └──[gap 발견]──► researching (루프)
```

**`ready` 승격 게이트 (Dialectical Gate, §8.6.2)**

| # | 조건 |
|---|---|
| G1 | core 주장 카드마다 `rebuttal_conditions` ≥ 1 |
| G2 | 모든 반증조건의 `resolution ≠ null` |
| G3 | grounds 출처가 독립된 T1~T2 ≥ 2개 |
| G4 | core 근거에 미해소 재인용(`is_secondhand`) 없음 |
| G5 | 논리 오류 스캔 경고를 인간이 확인·처리 |

> **강제 승격(override)을 허용한다.** 단 사유를 기록하고 절에 🔶 표식이 남으며,
> Export 시 "검증 미완 구간" 목록에 자동 포함된다. 차단이 아니라 **부채 가시화**.

### 6.3 카드

```
digested → active ──[출처 링크 깨짐 / 반박 카드 등장 / confidence≤2 & 90일]──► needs_recheck
                                                                                    │
                        active ◄──[재소화]──────────────────────────────────────────┤
                                                                                    ▼
                                                                                 retired
```

## 8. 저술 특화 기능 (이번 재검토의 핵심 추가분)

기존 "아이디어 관리" 구상에서 **저술 목적**으로 확정되며 새로 필요해진 것들:

### 8.1 Thesis 정렬 검사
모든 카드/절이 `work.thesis`에 기여하는지 점검. 벗어난 카드는 "다른 책 후보"로 분리 제안.
→ **책이 산으로 가는 것을 막는 유일한 장치.**

### 8.2 목차 우선 vs 카드 우선 양방향
- Top-down: 목차 먼저 → 빈 절이 리서치 요청 생성
- Bottom-up: 카드 쌓임 → 클러스터링으로 목차 초안 제안
- 두 방향 모두 지원해야 실제 저술 과정과 맞는다.

### 8.3 문체 프로파일 (Voice Profile)
`my_take` 필드의 누적 텍스트 = 저자의 실제 문체 샘플.
초고 생성 시 이를 스타일 레퍼런스로 주입 → AI 초고가 처음부터 내 목소리에 가깝게 나온다.
> 별도 문체 학습 데이터를 만들 필요가 없다는 게 이 설계의 이점.

### 8.4 인용·참고문헌 자동화
- 각주/미주 스타일 선택 (APA / Chicago / 한국식)
- export 시 `sources` 테이블에서 참고문헌 자동 생성
- 링크 소멸 대비 `archive_path` 스냅샷

### 8.5 원고 Export
Markdown → DOCX / EPUB / PDF. 장별 분리 export. 편집자 코멘트용 DOCX 우선.
### 8.6 반론 강제 — 논리 기반 (Dialectical Gate)

단순히 "반박 카드 1장 있으면 통과"는 형식주의로 전락한다. **주장의 논리 구조를 분해해 반증 가능 지점을 찾고, 그 지점이 처리되었는지** 검사한다.

#### 8.6.1 주장 카드의 논리 구조

`card_type = argument`인 카드는 논증 필드를 갖는다 (Toulmin 모델 축약):

| 필드 | 의미 | 예시 |
|---|---|---|
| `claim` | 주장 | 조직 신뢰는 거래비용을 낮춘다 |
| `grounds` | 근거 | 고신뢰 조직의 계약·감사 비용이 유의하게 낮음 (Zak 2017) |
| `warrant` | 근거→주장 연결 논리 | 감시 필요가 줄면 조정비용이 준다 |
| `qualifier` | 적용 범위·조건 | 조직 규모 100인 이상, 서구 기업 표본 |
| `rebuttal_conditions[]` | **이 주장이 무너지는 조건** | 신뢰가 담합·집단사고를 낳아 비용이 되는 경우 |

> `rebuttal_conditions`는 **인간이 소화 시점에 직접 작성한다.** AI가 채우면 원칙 1 위반이며, 무엇보다 자기 주장의 약점을 스스로 아는 것이 저술의 핵심 노동이다.

#### 8.6.2 게이트 통과 조건

절(node)을 `ready`로 올리려면, 그 절의 모든 `core` 주장 카드에 대해:

| # | 검사 | 통과 기준 |
|---|---|---|
| G1 | **반증조건 명시** | `rebuttal_conditions` ≥ 1개 작성됨 |
| G2 | **반증조건 처리** | 각 조건마다 다음 중 하나가 존재: ① 반박하는 `contradicts` 카드 ② 범위를 좁힌 `qualifier` 갱신 ③ 명시적 `한계 인정` 메모 |
| G3 | **출처 독립성** | `grounds`가 서로 다른 저자·기관의 T1~T2 출처 **2개 이상** |
| G4 | **재인용 해소** | `is_secondhand = true` 출처가 core 근거로 쓰이지 않음 |
| G5 | **논리 오류 스캔** | 자동 검사 통과 (아래) |
| G6 | **본문 확보 수준** | core 근거 중 `access_level = abstract_only`가 **50% 이하** |

**G3 보조 규칙 (OA 전용 운영, §8.9)**
초록만 확보된 출처는 G3의 "독립 출처 2개"에서 **0.5개로 계산**한다.
→ 초록 2편만으로는 G3를 통과할 수 없고, 최소 1편은 본문 확보가 필요하다.

**G2가 핵심이다.** 반박 카드를 억지로 만들 필요는 없다. **"이 조건에서는 내 주장이 안 통한다"를 본문에 쓰는 것도 통과**다. 오히려 그게 더 학술적이다.

#### 8.6.3 논리 오류 자동 스캔 (G5)

AI가 카드의 `claim`/`grounds`/`warrant`를 읽고 아래 패턴을 지적한다. **경고일 뿐 차단하지 않는다** — 판단은 인간이 한다.

| 패턴 | 탐지 신호 |
|---|---|
| 상관≠인과 | grounds가 상관관계인데 claim이 인과를 주장 |
| 성급한 일반화 | 표본 범위 < claim 범위 (qualifier 누락) |
| 순환논증 | warrant가 claim을 재진술 |
| 단일출처 의존 | grounds 출처 1개 |
| 표본 편향 | qualifier에 지역·시기·업종 제약이 있는데 claim은 보편 |
| 권위에 호소 | grounds가 "저명한 X가 말했다"뿐, 데이터 없음 |
| 시대 낙후 | 실증 데이터 출처가 15년 이상 경과 |
| **초록 과의존** | grounds가 전부 `abstract_only` 출처 |
| **OA 편향** | 특정 분야에서 OA 논문만 인용 — 유료 문헌에 반대 결론이 있을 가능성 |
| **권위 누락** | 해당 주제 상위 인용 문헌이 근거에서 빠짐 (§8.9.5) |

> AI는 오류를 **지적만** 한다. 수정 문장을 쓰지 않는다. (원칙 1)

#### 8.6.4 대중서일 때

`rigor_profile = trade`여도 **G1~G5는 동일하게 적용한다.** 달라지는 것은 출력뿐:

| | academic | trade |
|---|---|---|
| 검증 게이트 | G1~G5 | **G1~G5 (동일)** |
| 반증조건 본문 노출 | 필수 (별도 절/각주) | 선택 (미주로 이동 가능) |
| 인용 표기 | 본문 각주 | 미주 / 권말 출처 |
| qualifier 서술 | 명시적 문장 | 자연스러운 서술로 흡수 |

> **핵심:** 대중서는 *덜 엄격하게 조사한 책*이 아니라 *엄격하게 조사한 뒤 쉽게 쓴 책*이다.
> 검증을 느슨하게 하는 옵션은 제공하지 않는다.

### 8.7 학술 수준 인용 체계

- **DOI/ISBN 입력 → CrossRef·OpenLibrary API로 서지정보 자동 완성.** 수기 입력 오류 제거
- **인용구 원문 대조:** `excerpt.text`가 소스 스냅샷에 실제 존재하는지 문자열 검증 → `locator_verified`
- **페이지 로케이터 필수:** 직접 인용은 페이지/절 번호 없으면 저장 불가
- **재인용 추적:** `is_secondhand = true` 시 "원전 확인" 과제를 자동 생성. 미해소 시 G4에서 차단
- **참고문헌 자동 생성:** CSL(Citation Style Language) 기반, Chicago/APA/한국식 전환
- **출처 스냅샷:** 웹 출처는 저장 시점 로컬 아카이브 + `accessed_at` 기록

### 8.8 리서치 깊이 — 학술 수준

리서치 실행 시 아래 순서로 소스를 탐색한다.

```
1차: 학술 DB          OpenAlex / Semantic Scholar / CrossRef / arXiv
                      → 피어리뷰 논문, 인용수, 원논문 PDF
     ↳ Unpaywall로 OA 전문 자동 확보 (§8.9)
2차: 1차 사료          기관 원자료, 통계청·OECD·World Bank, 법령·판례, 기업 공시
                      → 구독 무관 전문 무료. OA 운영에서 특히 중요
3차: 학술서·전문서     Google Books / 도서관 API / DOAJ
4차: 보조 자료         주요 언론, 기관 보고서   ← T3, 보강용
   ✗ 블로그·요약사이트  ← T4, 원전 링크 발견 용도로만 사용. 근거로 승계 금지
```

**리서치 산출물 규격**
- 각 요점마다 출처 번호 + tier 표시 필수
- **반대 견해 섹션 필수** — 없으면 "반대 문헌 미발견"을 명시하게 함
- 원논문 PDF 확보 시 로컬 저장 (소화 시 인용구 대조에 사용)
- 분량 상한 유지 (R1 병목 방지) — **깊이는 늘리되 길이는 늘리지 않는다**

> 학술 깊이가 곧 자료 분량 증가를 의미하면 소화 병목(R1)이 터진다.
> 원칙: **T4 잡음을 걷어낸 자리에 T1~T2를 채운다. 총량은 그대로.**

### 8.9 오픈 액세스 우선 전략 (D7)

**유료 저널 구독 없이 운영한다.** OA만으로 학술 수준 검증이 가능하다는 전제이며, 실제로 상당 부분 가능하다. 다만 **불가능한 지점을 시스템이 인지하고 표시하는 것**이 이 절의 목적이다.

#### 8.9.1 OA 소스 우선순위

| 순위 | 소스 | 확보 가능 | 비고 |
|---|---|---|---|
| 1 | **Unpaywall / OpenAlex** | 합법 OA 전문 PDF | DOI로 OA 사본 자동 탐색. **핵심 도구** |
| 2 | **arXiv / bioRxiv / SSRN** | 프리프린트 전문 | ⚠ 피어리뷰 전일 수 있음 → `peer_reviewed=false` |
| 3 | **PubMed Central** | 의학·생명 전문 | 완전 무료 |
| 4 | **DOAJ** | OA 저널 전문 | |
| 5 | **Semantic Scholar API** | 초록 + 인용맥락 + 일부 전문 | 무료 API 키 |
| 6 | **기관 리포지터리** | 저자 최종본 (postprint) | RISS, 대학 dCollection |
| 7 | **Google Scholar 링크** | 저자 개인 페이지 사본 | |
| 8 | **1차 사료** | 통계청·OECD·World Bank·법령·판례·공시 | **구독 무관, 전문 무료. 매우 강력** |

> **핵심 통찰:** 유료 저널을 못 봐도 **1차 사료는 전부 무료**다.
> 통계·법령·공시·기관 원자료는 오히려 논문보다 강한 T1 근거다.
> OA 제약은 "논문 접근"의 제약이지 "근거 확보"의 제약이 아니다.

#### 8.9.2 `sources.access_level` — 확보 수준 명시

| 값 | 의미 | core 근거 사용 |
|---|---|---|
| `fulltext` | 전문 확보 (PDF/HTML 로컬 저장) | ✅ 제한 없음 |
| `postprint` | 저자 최종본 (페이지 번호 상이 가능) | ✅ 페이지 인용 시 주의 표기 |
| `preprint` | 프리프린트 (미피어리뷰) | ⚠ 가능하나 `peer_reviewed=false` 명시 |
| `abstract_only` | **초록만 확보** | ⚠ G3에서 0.5개로 계산, G6 상한 적용 |
| `citation_only` | 서지정보만 (본문 미확인) | ❌ core 근거 사용 불가 |

#### 8.9.3 초록만 있을 때의 규칙

초록 기반 카드를 **금지하지 않는다.** 금지하면 조사가 멈춘다. 대신:

1. `access_level = abstract_only` 강제 기록
2. **직접 인용 금지** — 초록 문장을 원문 인용으로 쓸 수 없다 (`excerpts` 생성 차단)
3. **수치 인용 금지** — 초록의 수치는 반올림·요약된 경우가 많다
4. 카드에 🔒 표식, `confidence` 상한 **3**
5. G3에서 0.5개 계산, G6에서 core 근거의 50% 초과 불가
6. **"본문 확보 과제"** 자동 생성 → 나중에 도서관·저자 요청·OA화 시 해소

> **왜 이렇게까지:** 초록만 읽고 논문을 인용하는 것은 학계에서 가장 흔한 부실 인용이다.
> 초록은 저자의 *주장 요약*이지 *검증된 결과*가 아니다. 한계·표본·유의수준이 전부 빠져 있다.
> 그런데 이걸 막으면 조사가 마비되므로 **허용하되 등급을 낮추고 흔적을 남긴다.**

#### 8.9.4 본문 확보 대안 (구독 없이)

시스템이 `abstract_only` 카드에 대해 아래 경로를 순차 안내한다:

```
1. Unpaywall 재조회        시간이 지나 OA 전환되었을 수 있음 (엠바고 해제)
2. arXiv/SSRN 프리프린트    동일 논문의 프리프린트 판 탐색
3. 저자 개인 홈페이지·ResearchGate
4. 기관 리포지터리 postprint
5. 저자에게 직접 이메일 요청   ← 응답률 의외로 높음. 템플릿 제공
6. 공공도서관 / 국회도서관 원문복사
7. 유사 주제의 OA 대체 문헌으로 근거 교체   ← 가장 실용적
```

**7번이 실무적으로 가장 자주 쓰인다.** "이 논문이어야만 한다"는 경우는 드물고, 대개 같은 결론을 지지하는 OA 문헌이 존재한다.

#### 8.9.5 OA 편향 경고

OA에만 의존하면 생기는 체계적 편향을 대시보드에서 경고한다.

**실측 데이터 (OpenAlex, 2015년 이후 논문, 2026-07 조회)**

| 분야 | 논문 수 | OA 비율 |
|---|---:|---:|
| Physics | 28.9M | 69.5% |
| Medicine | 30.2M | 58.0% |
| Computer Science | 50.8M | 56.4% |
| Sociology | 11.5M | 54.0% |
| Economics | 8.7M | 53.5% |
| Business | 11.2M | 52.2% |
| Philosophy | 15.3M | 49.4% |
| History | 5.9M | 40.0% |

> **통념 교정:** "인문·사회는 OA가 빈약하다"는 널리 퍼진 인식은 **총량 기준으로는 사실이 아니다.**
> 사회학 54%, 경제학 53.5%로 CS(56.4%)와 차이가 없다. 실제로 낮은 것은 History(40%) 정도다.

**진짜 위험은 총량이 아니라 권위 분포다.**

| | 물리·CS | 사회·경영 |
|---|---|---|
| OA 총량 | 높음 | **비슷하게 높음** |
| **최상위 저널 OA** | **높음** (arXiv 선공개 관행) | **낮음** (구독 저널이 정설 형성) |
| 실무 영향 | 거의 무손실 | **정설 누락 위험** |

실측 예: `10.1038/nature12373` (Nature) → `green` OA, PDF 확보 성공.
`10.1257/aer.101.5.1649` (American Economic Review) → `closed`, 확보 불가.

> 사회과학은 **"논문은 열려 있지만 정설을 만드는 저널은 닫혀 있는"** 구조다.
> 따라서 OA 편향 경고는 *"OA 논문 비율"* 이 아니라
> **"해당 주제 상위 인용 문헌 중 확보 실패 비율"** 로 측정해야 한다.

**경고 항목**
- **권위 누락:** OpenAlex 인용수 상위 20편 중 `access_level=citation_only` 비율 ≥ 30%
- **프리프린트 과다:** 절 근거 중 `preprint` 비율 ≥ 25% → 피어리뷰 보강 권장
- **지역 편향:** 영어권 문헌만으로 구성 — 국내 맥락 주제일 때 경고
- **분야 특성:** History 등 OA 비율 낮은 분야는 1차 사료·단행본 비중 확대 안내

> 대시보드 경고 예: *"3장 주제의 상위 인용 문헌 20편 중 7편 확보 실패(35%). 정설이 누락되었을 수 있습니다."*

```
POST   /api/works/{id}/export?format=docx
```

### 9.1 `/digest` 는 원자적 트랜잭션

```
BEGIN
  INSERT knowledge_cards (인간 텍스트)
  INSERT sources (체크된 출처만)
  INSERT excerpts (담은 발췌만)
  UPDATE research_runs SET output_md = NULL, purged_at = now()
  UPDATE research_requests SET status = 'digested'
COMMIT
```

> 카드 생성과 자료 폐기가 분리되면 원칙 1이 깨진다. 반드시 한 트랜잭션.

### 9.2 초고 생성 프롬프트 계약

```
[시스템]
당신은 저자의 카드만을 재료로 초고를 작성한다.
- 카드에 없는 사실·수치·인명을 생성하지 마라. 절대 금지.
- 필요하지만 카드에 없는 내용은 정확히 [근거 부족: 무엇이 필요한지] 로 표기하라.
- 저자의 my_take 문체를 따르라.

[입력]
work.thesis / node.intent / node.target_length
cards: [{title, summary, key_points, my_take, role, excerpts}]
voice_samples: [my_take 최근 10개]

[출력]
{ body_md, gaps: [{position, missing_what, suggested_question}] }
```

`gaps`가 그대로 리서치 요청으로 전환된다 = 루프 완성.

## 11. 개발 로드맵

### Phase 1 — 정제 루프 (5주) · MVP
목표: **학술 수준으로 검증된 카드가 쌓이기 시작한다**
- Capture / Inbox
- 리서치 요청 → **학술 DB 우선 AI 리서치** → Digest Workbench
- 폐기 트랜잭션, 붙여넣기 차단
- **출처 tier 등급 + DOI/ISBN 서지 자동완성 + 페이지 로케이터 필수**
- **Unpaywall OA 전문 확보 + `access_level` 등급화**
- Library 기본 검색

✅ 완료 기준: 2주간 실사용해 카드 20장 축적 (T1~T2 출처 비율 ≥ 70%, 전문 확보율 ≥ 60%)

### Phase 2 — 저술 구조 + 논증 검증 (4주)
목표: **책의 뼈대가 생기고, 주장이 검증된다**
- Work / Outline Board (학술서·대중서 병행 관리)
- 카드 배치 (다중 저작물 배치 지원), 커버리지 진단
- **논증 필드 (claim/grounds/warrant/qualifier/rebuttal_conditions)**
- **Dialectical Gate G1~G5 + override**
- **논리 오류 자동 스캔**
- 유사 카드 추천, 관계 링크, 그래프

✅ 완료 기준: 목차 1개 완성 + 카드 50장 배치 + 절 1개 게이트 통과

### Phase 3 — 집필 (4주)
목표: **원고가 나온다**
- Writing Studio, AI 초고 생성
- gap → 리서치 요청 루프
- 각주·인용, Export (DOCX)

✅ 완료 기준: 1개 장(章) 초고 → 퇴고 완료

### Phase 4 — 지속성 (3주)
- Dashboard, 경고 시스템
- 문체 프로파일, 반론 강제
- 카드 재소화, 출처 아카이빙
- 텔레그램 캡처

| R12 | **OA 편향** — 유료 문헌에 반대 결론이 있는데 못 봄 | 🟡 | G5에 `OA 편향` 탐지 추가. 대시보드에서 분야/지역/출판사 편향 경고 (§8.9.5) |
| R13 | **프리프린트 과신** — 미검증 결과를 정설로 오인 | 🟡 | `peer_reviewed=false` 명시. 절별 프리프린트 비율 경고 |

**R4 보강안:** 초고 생성 후 자동 검증기 — 원고에 등장하는 고유명사·수치를 추출해 사용된 카드 텍스트에 존재하는지 대조하고, 없으면 강조 표시. 환각 탐지의 실용적 방어선.

## 14. 결정 사항 및 미결

### 14.1 확정 (2026-07-25)

| # | 항목 | 결정 |
|---|---|---|
| D1 | **저작물 성격** | **학술서·대중서 병행 집필.** 두 종류를 동시에 관리 |
| D2 | **검증 기준** | **항상 학술서 수준.** `rigor_profile`은 *출력 형식*만 바꾸고 검증 게이트는 동일 |
| D3 | **인용 엄격도** | DOI/ISBN 서지 자동완성, 페이지 로케이터 필수, 인용구 원문 대조, 재인용 추적 |
| D4 | **리서치 깊이** | 학술 DB 우선(Semantic Scholar/OpenAlex/CrossRef/arXiv) → 1차사료 → 학술서 → 보조자료. T4는 근거 승계 금지 |
| D5 | **반론 강제** | 형식적 카드 수 세기가 아닌 **논리 기반 Dialectical Gate (G1~G5)**. Toulmin 논증 구조 + 반증조건 처리 |
| D6 | **게이트 위반 시** | 차단이 아니라 **override + 부채 가시화** |
| D7 | **문헌 접근** | **오픈 액세스 전용 운영.** 유료 저널 구독 없음. Unpaywall/OpenAlex/arXiv/PMC/DOAJ + 1차 사료로 커버 (§8.9) |
| D8 | **초록만 확보 시** | 카드 작성 **허용**하되 `access_level=abstract_only` 기록 · 직접인용/수치인용 금지 · confidence 상한 3 · G3에서 0.5개 계산 |

> **D2의 함의:** 대중서 원고도 학술 수준으로 검증된 카드 위에서 쓰인다.
> 검증을 느슨하게 하는 옵션은 **의도적으로 제공하지 않는다.**
> 대중서는 *덜 조사한 책*이 아니라 *엄격히 조사한 뒤 쉽게 쓴 책*이다.

### 14.2 D1의 구조적 함의 — 카드 공유 정책

학술서·대중서 병행이 확정되면서 새로 결정이 필요해진 지점:

- 카드는 `work_id`에 **묶이지 않는 것을 기본**으로 한다 (`work_id` nullable 유지)
- 대신 `card_assignments`로 **여러 저작물의 목차에 동시 배치** 가능
- 같은 카드가 학술서에서는 각주+qualifier 명시로, 대중서에서는 서술 흡수로 쓰인다
- **자기표절 경고:** 동일 카드가 2개 저작물의 `core`로 배치되면 경고 표시

> 이게 이 시스템의 큰 이점이 된다. **한 번 소화한 지식으로 두 권을 쓴다.**
> 학술서에서 엄밀히 다룬 주제를 대중서에서 쉽게 풀어쓰는 것이 자연스럽게 지원된다.

### 14.3 남은 미결

1. **기존 자료 임포트** — 이미 가진 노트/스크랩. 요약 재작성을 강제할 것인가, 예외를 둘 것인가?
2. **집필 분야** — 인문·사회·과학 중 무엇인가? **OA 커버리지가 분야마다 크게 다르므로 D7 실효성 판단에 직결**
3. **모바일 캡처** — 텔레그램 봇으로 충분한가?
4. **문체 프로파일 분리** — 학술서와 대중서는 문체가 다르다. `voice_profile`을 저작물별로 둘 것인가?

> **2번이 가장 시급하다.** 단 §8.9.5 실측 결과, 통념과 달리 **분야별 OA 총량 차이는 크지 않다**(사회학 54% ≈ CS 56%).
> 실제 변수는 *총량*이 아니라 *해당 분야 최상위 저널의 개방 여부*다.
> 사회과학·경영이라면 §8.9.4의 대체 경로(특히 7번 OA 대체문헌 교체)와 1차 사료 비중이 중요해진다.
